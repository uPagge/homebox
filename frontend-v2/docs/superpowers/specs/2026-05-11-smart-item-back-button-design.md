# Smart Back Button on Item Page

**Date:** 2026-05-11
**Status:** Approved
**Scope:** frontend-v2

## Problem

Когда пользователь меняет локацию вещи (через инлайн-edit «Детали» или через `MoveScannerSheet`) на странице `/items/[id]`, он остаётся на той же странице. После переноса хочется продолжить работу с другими вещами в **исходной** локации — но обратной связи к ней нет:

- Кнопка «Назад» (`pages/items/[id].vue:272`) — мелкая, серая, без указания цели; делает `router.back()` и пользователь её не замечает.
- Чип локации (`pages/items/[id].vue:313-321`) после переноса указывает на **новую** локацию, а не на исходную. Естественный визуальный таргет ведёт не туда.
- Если зашёл по прямой ссылке / из QuickMenu / поиска — `router.back()` вообще уведёт мимо исходной локации.

Итог: возврат технически возможен, но не находится. Пользователь жалуется «не могу вернуться в ту же локацию».

## Решение

Кнопка «Назад» на странице айтема должна явно знать origin и подписываться его именем. Origin прокидываем через query-параметр URL.

### Механика

1. **Origin в URL.** Ссылки на айтем внутри локации формируются как `/items/<id>?from=<locationId>`.
2. **Чтение origin.** Страница айтема читает `route.query.from`. Если есть и резолвится в имя локации через `useLocationTree` — кнопка превращается в `← <LocationName>` и ведёт прямо в `/locations/<from>`. Если нет — текущее поведение «← Назад» + `router.back()`.
3. **URL не мутирует при смене локации айтема.** `saveEdit`/MoveScannerSheet меняют только `item.location`, query-параметр `from` остаётся прежним. Это и есть ключевой фикс: после переноса A→B кнопка всё ещё ведёт в A.

### Файлы под правку

| Файл | Изменение |
|---|---|
| `components/items/ItemCard.vue:45` | `:to` расширяется до `{ path: '/items/<id>', query: { from: currentLocationId } }`, когда `currentLocationId` задан |
| `components/items/ItemListRow.vue` (аналогичный NuxtLink) | Те же изменения |
| `pages/items/[id].vue:270-276` | Переписать кнопку «Назад»: читать `route.query.from`, резолвить имя через `tree.getName(from)`, бранчиться на label/click |

В `pages/locations/[id].vue:438,452` уже передаётся `:current-location-id="locationId"`, ничего трогать не нужно.

### Поведенческие случаи

| Юзер | URL айтема | Подпись | Куда ведёт |
|---|---|---|---|
| Пришёл из `/locations/A` | `/items/X?from=A` | `← Кухня` | `/locations/A` |
| Перенёс X в B, остался на айтеме | `/items/X?from=A` | `← Кухня` | `/locations/A` ✓ ключевой фикс |
| Ушёл в B по чипу → браузерный back | `/items/X?from=A` | `← Кухня` | `/locations/A` |
| Открыл айтем из QuickMenu / прямой ссылки | `/items/X` | `← Назад` | `router.back()` |
| Tree ещё не загрузился, имени нет | `/items/X?from=A` | `← Назад` (фолбэк) | `/locations/A` (push по id) |
| `from` задан, но локация удалена | `/items/X?from=A` | `← Назад` (фолбэк) | `router.back()` |

### Вне скоупа

- **Метки / поиск как origin.** Сейчас `/labels/[id]` и поиск тоже навигируют в айтем, но фикс не покрывает их. Расширение возможно через generic `?from=/labels/L` позже.
- **Проброс origin при навигации айтем→айтем** (через parent-чип `pages/items/[id].vue:304-312`). Origin не наследуем: parent-айтем может лежать в другой локации, breadcrumb расползётся. Фолбэк на `router.back()` достаточен.
- **MoveScannerSheet / BatchLocationSheet.** Они не уводят со страницы; для них фикс не нужен.
- **Быстрый перенос с карточки без захода в айтем.** Отдельная UX-инициатива (см. Вариант 3 в обсуждении). Не часть этой спеки.

## Acceptance criteria

1. Из `/locations/A` клик по карточке вещи открывает `/items/X?from=A`, кнопка «Назад» подписана именем локации A.
2. После смены локации X на B (любым способом — инлайн или сканер) кнопка по-прежнему показывает имя A и ведёт в `/locations/A`.
3. Прямой переход на `/items/X` (без `from`) сохраняет текущее поведение: «← Назад», `router.back()`.
4. Сломанный/неизвестный `from` (локация удалена, tree не загружен) деградирует в «← Назад» без ошибок в консоли.
5. Линки в `ItemCard` и `ItemListRow` ведут себя одинаково.

## Out-of-the-way

- Никаких новых API-вызовов: имя локации берётся из уже загруженного `useLocationTree`.
- Никаких изменений в `MoveScannerSheet`, `BatchLocationSheet`, `pages/locations/[id].vue`.
- Объём правки ≈ 30–40 строк в 3 файлах.
