# Location Disambiguation in Pickers and Badges

**Date:** 2026-05-11
**Scope:** `frontend-v2/`

## Problem

В пикерах локаций (выбор куда переместить, фильтр, поиск) и в части бейджей рендерится только `location.name`. Если у разных родителей есть дочерние локации с одинаковыми именами (типичный пример: «Полка 1» в кухне и «Полка 1» в кладовке) — пользователь видит одинаковые пункты и не может выбрать правильный. См. репро: `Move scanner → Выбрать локацию → "Полка"`.

## Existing Infrastructure

Большая часть нужного уже есть.

`composables/use-location-tree.ts` экспонирует `useLocationTree()`. Композабл лениво грузит `GET /locations/tree`, кеширует в модульном `ref` (один fetch на сессию) и возвращает:

- `getPathString(id, sep?) → "Кухня › Шкаф › Полка 1"` — полный путь от корня до листа.
- `getName(id)`, `getPath(id)`, `ready()`, и т.п.

Дискриминатор пути — `' › '` (U+203A).

Уже потребляют этот композабл и **рендерят правильно**:
- `components/items/ItemCard.vue:18,30-33` — карточка вещи в сетке. Использует `pathString`, рендерит в `<bdi style="direction:rtl">` с `truncate` (приём «обрезаем начало, оставляем лист»), плюс `:title="pathString"` для tooltip.
- `components/items/ItemListRow.vue:18,32` — строка в списке (тот же приём).
- `components/locations/LocationCreateSheet.vue:16,50` — путь родителя при создании локации.
- `pages/locations/[id].vue:12` — детальная страница локации.

Эти места уже работают корректно, **трогать их не надо**.

Везде используется плоский `api.locations.getAll() → LocationOutCount[]` и рендерится только `loc.name`:

## Design

### Пикеры: двустрочный пункт

Каждый пункт пикера рендерится двумя строками:

```
Полка 1                              (0)
Кухня › Шкаф
```

- Первая строка: имя локации (`text-sm`), `(itemCount)` справа.
- Вторая строка: полный путь предков (`text-xs text-muted-foreground`). Если у локации нет родителей — вторая строка не рисуется (топовая локация).
- Поиск работает по имени, как сейчас (`loc.name.toLowerCase().includes(q)`).

**Источник данных:**
- Список и itemCount продолжаем брать из `api.locations.getAll()` — он и так уже фетчится. Меняется только рендер.
- Путь предков — `useLocationTree().getPathString(loc.id)`. Композабл может ещё не загрузиться (асинхронный fetch tree), в этот момент вторая строка не рисуется. После загрузки рендер обновится реактивно (`byId` — `ref<Map>`).
- Допустимо: если в дереве локация не нашлась (рассинхрон, новая), вторая строка отсутствует.

**Селектор `<select>` (точка 6):** нативный `<option>` не поддерживает двух строк. Туда подставляем строку `"Кухня › Шкаф › Полка 1"` (полный путь, имя — последний сегмент). Альтернатива — переписать `<select>` на кастомный пикер, но это вне скоупа.

### Бейджи: тот же паттерн, что в ItemCard

Везде, где сейчас рендерится `item.location.name` (точки 7-9), повторяем приём из `ItemCard.vue:30-33,90-99`:

```vue
const pathString = computed(() =>
  tree.getPathString(item.location.id) ?? item.location.name
);
```

```html
<bdi
  class="truncate text-start"
  style="direction: rtl"
  :title="pathString"
>{{ pathString }}</bdi>
```

- Если дерево ещё не загружено — fallback `item.location.name` (как и сейчас).
- RTL+truncate сохраняет видимым лист (последний сегмент), отрезается начало с многоточием.
- Tooltip даёт полный путь.

### Что не входит в скоуп

- `components/locations/LocationChildCard.vue` (рендерит список детей одной локации): родительский контекст там очевиден из контекста страницы.
- Главная страница, другие неупомянутые места: бейджей с локацией там нет либо они уже корректные.

## Implementation Notes

- Изменения изолированы в `frontend-v2/`. Бэкенд не трогаем (см. CLAUDE.md auto-memory).
- `useLocationTree()` уже синглтон на уровне модуля — повторные вызовы из новых мест не плодят fetch-ов.
- Никаких новых API-эндпоинтов и новых типов.

## Out-of-Scope (явно)

- Не вводим новых композаблов («use-location-paths» из ранних идей не нужен — `useLocationTree` уже даёт всё).
- Не переписываем `<select>` в `pages/items/[id].vue` на кастомный пикер — только подменяем текст опции на путь.
- Не меняем порядок сортировки в пикерах (как и было — по имени).
- Не трогаем `LocationOutCount` тип, не дополняем его на бэке.

## Verification

Ручная проверка после правки:

1. Создать две локации с одинаковым именем «Полка 1» в разных родителях.
2. Открыть `Move scanner → Выбрать локацию → "Полка"` — оба пункта должны быть видимо разными (под именем — разные родители).
3. Аналогично проверить: BatchLocationSheet, QuickAddSheet, FilterBar, QuickMenuDialog (Ctrl+K, ввести «Полка»).
4. В `pages/items/[id].vue → Редактировать детали → Место` — в `<select>` опции должны быть «Кухня › Шкаф › Полка 1» / «Кладовка › Полка 1».
5. Бейджи: открыть вещь, лежащую в одной из «Полка 1» — в чипе локации виден лист «Полка 1», на hover/tooltip — полный путь.
